# Agent 议事规则 · v0.5

> **版本纪律**:本文件顶部版本号 + 文末「验尸记录」区是本 skill 的升级口子——只增不删,
> 规则改动必须走文末修订流程。「改了什么/为什么」不在文件内重复记账,以 git commit 为准
> (`git log -- SKILL.md`);文件只留版本号 + 验尸记录里的教训本身。

## 何时用

两个及以上归属不同人的 agent,要在 GitHub 上对齐一份产物(方案/契约/接口/评审)。
单人单 agent 的活不用;纯代码 review 走 code-review/pr-fix。

## 角色判定(先分清你是哪边)

- **作者方**:产物是你方出的 → 走「作者方流程」;
- **评审方**:对方发 PR 请你参与 → 走「评审方流程」。

## 铁律(双方通用)

1. **署名**:每条 agent 评论首行 `🤖 <agent名> · 代表 @<人>`。只代表其人的项目发言。
2. **主题铁律**:每条评论第二行重申议题一句话;无前缀/无议题重申视为无效发言。
3. **读后发言**:发言前读完 PR 正文、全部评审对象、此前所有评论、自己项目的相关代码。
   主张必须附证据(文件/行号/链接);拿不出的标 `[未验证]`。
4. **阶段前缀**:`[议程] [报到] [意见] [回应] [综合] [定稿建议] [升级]`。
5. **锚定 head SHA**:一切复核表态必须写明所核的 commit(v0.4 新增·实测两次推送与复核时序交叉,
   无锚定就会对着不同版本空转)。
6. **不投票**。全员 `[同意]` 且无未解阻塞 → 定稿;`[综合]` ≤3 轮仍有阻塞 → `[升级]`
   各写 ≤10 行分歧摘要(立场+代价)@双方人类仲裁。
7. **评论是过程,正文是冻结**:共识写进 PR 正文冻结区/ADR 才算数;合并由人执行。
8. 24h 未响应可标 `[缺席]` 继续;缺席方处理由议题所有人裁定并写进定稿。
9. **落地闭环优先于共识本身**(v0.5 新增 · 参考 IETF "rough consensus and running code" /
   Linus "talk is cheap, show me the code")。议事目标是能落地的最小闭环,不是把责任厘清到
   万无一失就停;拒绝过度设计。`[综合]`/`[定稿建议]`若没有对应的下一步可执行动作
   (PR/commit/接口/脚本落地),不算闭环,继续标 `[待落地]`,不得进冻结区。

## 作者方流程

1. 发 PR:评审对象须含**可行级评论的 markdown**(纯 HTML 没法逐条锚定);PR body =
   `[议程]`(唯一议题+成功标准)+ 参与方 + 本规则全文 + 底部预留「冻结区(定稿后由人填写)」。
2. **多评审对象必须同步**(v0.4 新增·实测):若同时列了 HTML 呈现版与 md 事实源,措辞冲突会卡终审——
   修订必须两边落,或明写「语义以 md 为准」。
3. 起监听(会话内 Monitor,轮询评论/行级/review 三路):
   ```bash
   # 排除自己用 GitHub 登录名,绝不用署名前缀——友方 agent 可能同署名「🤖 Claude」(v0.4·实测踩坑)
   gh api "repos/<R>/issues/<N>/comments?since=$last" --jq --arg me "$(gh api user --jq .login)" \
     '.[] | select(.user.login != $me) | ...'
   ```
4. 回应姿势:逐条 `[回应]`(接受/不接受+理由);**修订必须落进 diff 才能请求最终 `[同意]`**,
   回应时注明修订 commit;涉及自家人拍板的先问人再回。
5. 一事一议执法:对方把实施细节(端点 spec 等)拖进架构议题时,礼貌拆分「另 PR 评审」。

## 评审方流程

`[报到]`(项目·现状·并入面·遗漏,附代码位置)→ `[意见]`(逐条:针对第 X 节第 Y 条·意见·
是否阻塞)→ 对方修订后按 head SHA 复核 → 分歧尽,给最终 `[同意]`(注明边界:同意≠开工授权)。

## 收官动作(强制,这是验尸口子)

定稿合并后,发起方 agent 必须:
1. 把冻结结论回写各决策票/ADR(修订记录);
2. **写一条验尸**:本次议事踩了什么坑(哪怕写「无」),按 postmortem-distill 蒸成 ≤1 行 delta,
   追加到本文件文末「验尸记录」区;
3. delta 若指向规则本身的缺陷 → 进「修订候选」,凑齐或遇阻断性坑时走修订流程升版。

## 修订流程(升级口子)

1. 修订动议只来自两处:验尸记录里的 delta,或用户直接指示;
2. 人确认后:改正文 + 版本号 +0.1;改了什么/依据哪条验尸写进 commit message,文件内不重复记。
3. 正在进行中的议事沿用其 PR body 里的版本,不追溯。

3. **2026-07-29 · PR #2049**:HTML 方案页与 md 摘要措辞漂移,customer-agent 与 Sales 各卡一轮终审 →
   delta:多评审对象必须同步修订(已入 v0.4 作者方流程 2)。
4. **2026-07-29 · PR #2049**:正面经验留档——「阻塞点候选」预标注(★)有效引导评审火力;
   对方 agent 均自发附代码行级证据,规则的证据条款是全场质量底座。无 delta,维持。
5. **2026-08-05 · PR #2231**:多阶段对接里「本次通过」被误当「下游跑通」是终审前最大语义错位,
   评审方主动索要把交付边界写进冻结区才补上 → delta(修订候选):冻结区模板增设必填条目
   「交付边界:本次通过 ≠ 下游 issue/联调完成」。另:对方按旧 head 报到(已留言告知新 head
   仍未锚新),因修订兼容未空转——低危,维持观察不立规。
6. **2026-08-11 · PR #2344**:把用户口述的「网页可通、只有 Bot 不行」写进 PR 正文的
   **「我方证据摘要」**(标了 `[未验证]`)。用户随后实测网页同样被拒,线索作废,我方自撤 →
   对方首条回应仍引用了它(说明标注挡不住)。**delta(修订候选):未经我方亲验的第三方口述
   不进「我方证据摘要」,另立「待我方核实」区** —— `[未验证]` 标注不够,**摘要这个位置
   本身就在传递可信度**。本次因自撤及时未造成往返,但风险是真的。
7. **2026-08-11 · PR #2344**:评审方要求「请据此修订冻结区」,而铁律 7 是「冻结区由人落笔」——
   两者互锁,谁都动不了。破法:作者方先落**「拟稿 · 待双方人类确认」**版,人确认后改定稿措辞
   (本次定稿时同步写入对方声明的同意边界原文)→ delta(修订候选):把这条写进作者方流程,
   省得每次现想。**另注意定稿时别凭印象填评论 id**(本次差点把猜的 id 写进冻结区,
   `gh api ... | last | .id` 核出来是错的)——冻结区是永久留痕,链接错了没人会回头查。
8. **2026-08-12 · PR#2403(agent-center × CRM-System · 15 帖 · 双方冻结)**:作者方把一项
   **人员分工候选**塞进 §8.1「拟冻结结论」表并自标「待对方人类确认」,而该表前言同时写着
   「以下每条均已获对方明确表态」—— 评审方指出**两者冲突,且位置本身就在传递「这是已达成的」,
   自标挡不住**。破法:新建独立区块「人类待确认项(不在冻结结论内)」移出该项,冻结表前言改**分层
   声明**(哪些是对方已技术表态 / 哪些只是我方人类决定而对方仅判「技术相容」)→
   **delta(修订候选):涉及人员、排期、资源的候选项一律不进冻结表,另立「人类待确认项」区;
   冻结表前言必须声明每条的表态层级,不得笼统写「均已表态」**。
   与验尸 #6 同源(摘要区/冻结表这类**位置本身携带可信度**),建议下次升版时合并成一条通则。
   ⚠️ 同轮另有一条方法论 delta:长文多轮增量修订时,作者方一路用「⚠️ 更正块」打补丁,
   导致**旧问法在正文里越积越多**(§7 问题表整表仍是现在时、§3.2/§4 C3 旧句仍在),
   评审方批评「不要只靠后面的更正块覆盖前文,读者仍会先读到错的那句」→
   **delta:被指出错误后要整条/整节重写 + 留一行 `📌 修订留痕`,并定期把全文收成一个版本;
   只追加更正块 = 错误陈述仍在正文里现行有效**。
   正面留档:本次作者方被逐条核出四处实质错误(事实所有权反转 / 措辞捅穿自己刚立的红线 /
   授权强度被读松 / 上述位置错误),**无一是作者方自查发现的** —— 规则里「主张必须附证据」
   与「复核必须锚定 head SHA」两条是本场质量的实际来源,维持不动。

   **delta(修订候选):议事第一帖发出前必须验证接入方的仓库身份 —— 拿己方文档里记录的
   snapshot SHA 去 `gh api repos/<对方仓库>/commits/<sha>` 验同源,并读对方仓库 description;
   别拿产品中文名当唯一识别键**(中文名会撞:本次「商务助理系统」同时是己方契约里另一处的
   `display_name`,正是这个撞名把人带沟里的)。

   一律列完整字面值,禁用 shell/文档展开语法**(冻结区是给人照抄进生产的,不是给人读的)。

   有效,维持。
